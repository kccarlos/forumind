# Contributing

Thanks for helping improve Forumind! Bug reports, ideas, docs fixes,
and code are all welcome. By taking part, you agree to follow the
[Code of Conduct](CODE_OF_CONDUCT.md).

## Before you start

- **Bugs and ideas:** open an [issue](https://github.com/kccarlos/forumind/issues).
  For anything bigger than a small fix, please open an issue first so we can
  agree on the approach before you spend time on it.
- **Security issues:** report privately, see [SECURITY.md](SECURITY.md).

## Setup

You need a Mac with Xcode 27 and Ruby with the `xcodeproj` gem. Full details
are in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).

```sh
gem install xcodeproj
ruby scripts/generate_project.rb
open Forumind.xcodeproj
```

For device builds, put your Team ID in `Config/DevelopmentTeam.txt` (copy
`Config/DevelopmentTeam.example.txt`); forks that sign also set
`BUNDLE_ID_PREFIX`. Never commit a project generated with your team.

## The generated Xcode project

`Forumind.xcodeproj` is generated by `scripts/generate_project.rb`
and committed. When you add, remove, or rename Swift files, tests, or
resources, or change a build setting:

1. Change the files (or the script, for build settings; don't edit build
   settings in Xcode).
2. Run `ruby scripts/generate_project.rb` **without** `DEVELOPMENT_TEAM` or
   `BUNDLE_ID_PREFIX` (move `Config/DevelopmentTeam.txt` aside if you have
   one).
3. Commit the project together with your change.

CI's `project-drift` job fails if the committed project doesn't match.

## Code style

- **Match the surrounding code.** SwiftUI, `@MainActor` app state in
  `AppModel`, small focused files, and Apple frameworks only. Please don't add
  third-party dependencies without discussing it in an issue first.
- Keep user-facing text short, friendly, and consistent with the rest of the
  app (for example "Ask the forum", "Settings › Browser").
- New features should work on iPhone and iPad, in light and dark mode, and
  with Dynamic Type.
- Anything that can reach the network must keep the app's privacy promises:
  forum cookies only to their own forum, forum content only to the AI
  provider the user chose, and no analytics. See [PRIVACY.md](PRIVACY.md).
- Add DEBUG launch arguments (`-dc-…`) for states that are hard to reach, and
  document them in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#debug-launch-arguments).

## Tests

- **Add or update unit tests** (`ForumindTests`) for every behavior
  change or bug fix. Unit tests must not need a network connection or an API
  key.
- Run them before opening a pull request:

  ```sh
  xcodebuild test -project Forumind.xcodeproj -scheme Forumind \
    -destination 'platform=iOS Simulator,name=iPhone 17' \
    -only-testing:ForumindTests CODE_SIGNING_ALLOWED=NO
  ```

- **UI tests** don't run in CI. If your change affects UI flows, run the
  relevant UI tests locally on a spare simulator (iPhone, and iPad for layout
  changes); see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#ui-tests).
- For UI changes, attach screenshots to the pull request. Use the offline
  sample data (`-dc-sample`), not real forum users.

## Filter lists

The ad-blocking rules in `Forumind/ContentBlocking/` are generated;
don't edit the JSON by hand. A weekly workflow opens a pull request with
updates. To update or change the conversion yourself, see
[docs/AD_BLOCKING.md](docs/AD_BLOCKING.md):

```sh
scripts/adblock/run_tests.sh
scripts/adblock/update_rules.sh
```

## Commits and pull requests

- Write commit messages as a short imperative summary with a type prefix,
  for example `fix: keep chat drafts when switching forums`,
  `feat: …`, `docs: …`, `ci: …`, `test: …`, `chore: …`. Add a body when the
  "why" isn't obvious.
- Keep pull requests focused on one change. Fill in the template, and make
  sure CI is green.
- Don't commit secrets, API keys, Team IDs, provisioning files, or personal
  data.
